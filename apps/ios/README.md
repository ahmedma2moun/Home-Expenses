# apps/ios — HomeExpenses

SwiftUI, iOS 17+, MVVM. Source lives under `HomeExpenses/`:

```
HomeExpenses/
├── App/                     # @main entry point + RootView (the 3-tab shell)
├── Features/
│   ├── Summary/              # Home tab: month total, per-category totals, drill-down, "+" FAB
│   ├── Capture/               # PhotosPicker multi-select, reorderable thumbnails, "Analyze"
│   ├── Parsing/                # polls receipt status, retry on failure
│   ├── Review/                 # editable item list, category picker, mismatch banner, confirm
│   ├── Orders/                 # month-paged list + full edit form
│   └── Analytics/              # month-over-month category comparison + drill-down
├── Core/
│   ├── Networking/{APIClient.swift, APIError.swift, AppConfig.swift, DTOs/}
│   ├── DesignSystem/          # Money+FormatStyle, MonthLabel, FlexibleDateParser, OrderGroupView
│   └── Media/                  # ImagePreprocessor — downscale/JPEG re-encode before upload
└── Resources/                # Info.plist, Debug/Release xcconfig, Assets.xcassets
```

**Not present:** a `Settings` feature, a `Core/Persistence/` folder, or any SwiftUI `Charts` usage —
PROJECT_SPEC.md §2/§10 describe all three; none are built yet. See the gaps list below.

## The Xcode project is generated, not hand-authored

`apps/ios/HomeExpenses.xcodeproj` is real and checked into git (`project.pbxproj`,
`project.xcworkspace`, a shared scheme) — this used to be a from-scratch scaffolding step, it isn't
anymore. It's generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from
`apps/ios/project.yml`: one `HomeExpenses` application target, iOS 17 deployment target, Swift 6
with strict concurrency, no SPM/CocoaPods dependencies, no test target (`testTargets: []` — see
Testing below).

**If you edit `project.yml`, regenerate before reopening Xcode:**

```bash
brew install xcodegen   # once
cd apps/ios && xcodegen generate
```

`project.yml` deliberately does **not** use XcodeGen's `info:` block to manage `Info.plist` — doing
so would regenerate and silently wipe the hand-written keys in it (`API_BASE_URL`,
`NSCameraUsageDescription`, etc.). Edit `Resources/Info.plist` directly instead.

## What's actually built vs. PROJECT_SPEC.md §10

- **Four tabs** (`RootView`): **Home** (`Features/Summary`), **Orders**, **Analytics**,
  **Insights**. Capture, Parsing, and Review aren't tabs — they're a modal flow (`ReceiptFlowView`)
  launched from Home's "+" toolbar button.
- **Capture** uses `PhotosPicker` only (max 6 images) — no camera capture, no `VisionKit` document
  scanner, despite what the spec describes.
- **Analytics** is a month-over-month category comparison with a drill-down, not a Swift Charts
  trend view — there's no `import Charts` anywhere in the project. The AI narrative UI isn't an
  Analytics "Compare months" sheet either — it's its own **Insights** tab (`Features/Insights/`),
  which calls the now-live `POST /analytics/compare` (see `docs/api.md`).
- **Orders** has no search-by-merchant/item and no category filter.
- **No Settings screen** — no account/currency/sign-out/delete-account UI at all.
- **No offline cache** — no SwiftData, no `@Model`/`ModelContainer`/`ModelContext` anywhere. Nothing
  is cached for offline read, and there's no draft queue for captured-but-unsent receipts.
- **No authentication** — no Sign in with Apple, no JWT storage, no Keychain use, no refresh logic.
  `Core/Networking/APIClient.swift` sends no `Authorization` header at all; the backend currently
  resolves every request to one hardcoded dev user regardless (see the root `README.md`'s Status
  section and `docs/api.md`'s Conventions).
- **Image upload path** doesn't match PROJECT_SPEC.md §2's direct-to-blob design — there is no blob
  storage anywhere in this system. `Core/Media/ImagePreprocessor.swift` downscales to a 1568px long
  edge and re-encodes as JPEG (q≈0.8) via `UIGraphicsImageRenderer` (which also strips EXIF/GPS as a
  side effect), and `CaptureViewModel` base64-encodes the result directly into the
  `POST /api/v1/receipts` JSON body. A failed parse's retry (`POST /receipts/:id/reparse`) has to
  resend the same images for the same reason — the server never persists them.
- **Money** is `Decimal` everywhere, decoded from wire strings via a `MoneyString` wrapper
  (`Core/DesignSystem/Money+FormatStyle.swift`) — never `Double`. `quantity` stays a plain number,
  matching `docs/api.md`.
- No force-unwraps, `try!`, or `as!` anywhere in the app (checked by grep) — the one `fatalError` is
  in `AppConfig.apiBaseURL`, guarding a genuinely-unrecoverable missing/invalid `API_BASE_URL` in the
  active xcconfig.

## Testing

None yet — no `XCTest`/`XCTestCase`, no `*Tests.swift` files, and `project.yml`'s
`scheme.testTargets` is explicitly `[]`. Verification today is `swiftc -typecheck -swift-version 6
-strict-concurrency=complete` over the source tree, run by hand — see the CI caveat below.

## No CI

There is no `.github/workflows/ios-ci.yml` — no `.github/` directory exists anywhere in this repo.
Nothing builds, typechecks, or tests this app automatically on a push or PR yet.

## Config

`Resources/Debug.xcconfig` / `Release.xcconfig` set `API_BASE_URL`, read at runtime via
`AppConfig.apiBaseURL` (`Core/Networking/AppConfig.swift`) from `Info.plist`. No secrets live in
this app — no AI provider credential (Gemini or Anthropic, see `AI_PROVIDER.md`) ever ships to iOS;
the phone only ever talks to the backend, which holds whichever key is configured (CLAUDE.md rule 5).
